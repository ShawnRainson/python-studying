1. Самая важная мысль

Начнём с того, что немного изменим твоё привычное представление.

Ты раньше говорил примерно так:

«Переменная a хранит значение 10».

Для начала это удобная модель. Но технически правильнее думать так:

Имя a ссылается на объект 10.

Например:

a = 10

Можно представить это так:

a ───────► 10

a — это имя.

10 — это объект.

И это очень важно.

2. А что происходит здесь?
a = 10
b = a

Не создаётся ситуация:

a ──► 10
b ──► 10

в смысле «у каждого своя копия».

Мы можем представить это так:

       ┌──────► 10
a ─────┤
b ─────┘

Оба имени ссылаются на один объект.

Проверить идентичность объектов можно с помощью is:

a = 10
b = a


print(a == b)
print(a is b)
3. == против is

Вот здесь запомни фундаментальное различие.

==

Проверяет:

равны ли значения объектов?

a = [1, 2, 3]
b = [1, 2, 3]


print(a == b)

Получим:

True

Потому что содержимое одинаковое.

Но:

print(a is b)

даст:

False

Потому что это два разных объекта.

Можно представить:

a ───► [1, 2, 3]


b ───► [1, 2, 3]

Содержимое одинаковое → == → True.

Объекты разные → is → False.

Коротко:
==  → равенство
is  → идентичность
4. Теперь самое интересное — изменяемость

Объекты в Python условно делятся на:

Immutable — неизменяемые

Например:

int
float
bool
str
tuple
Mutable — изменяемые

Например:

list
dict
set

И вот здесь нужно немного поправить твоё представление из диагностики.

Когда ты делаешь:

x = 10
x = 20

не происходит изменения объекта 10.

Происходит примерно это:

x ───► 10


x ───► 20

Имя x просто перестало ссылаться на старый объект и стало ссылаться на другой.

5. Почему со списком всё иначе?

Смотри:

numbers = [1, 2, 3]


numbers.append(4)

Здесь объект списка изменяется:

numbers ───► [1, 2, 3]
                    ↓
numbers ───► [1, 2, 3, 4]

Сам объект остался тем же.

6. И теперь тот самый момент из диагностики
a = [1, 2, 3]
b = a


b.append(4)


print(a)
print(b)

Что здесь произошло?

После:

b = a

получаем:

a ─────┐
       ▼
   [1, 2, 3]
       ▲
       │
b ─────┘

А потом:

b.append(4)

мы изменяем сам объект списка.

Поэтому:

a → [1, 2, 3, 4]
b → [1, 2, 3, 4]

Это не потому, что b каким-то образом «изменил a.

Они вообще указывали на один и тот же список.

7. Как сделать отдельную копию?

Можно:

a = [1, 2, 3]
b = a.copy()


b.append(4)

Теперь:

a ───► [1, 2, 3]


b ───► [1, 2, 3, 4]

И:

print(a)

даст:

[1, 2, 3]
8. Но тут есть ловушка 👀

Посмотри:

a = [[1, 2], [3, 4]]
b = a.copy()

На первый взгляд кажется, что мы полностью скопировали a.

Но это поверхностная копия.

Условно:

a ─────► [ ───► [1, 2]
           └──► [3, 4] ]


b ─────► [ ───► [1, 2]
           └──► [3, 4] ]

Внешние списки разные.

Но внутренние списки всё ещё общие.

Поэтому:

b[0].append(100)

может изменить и a.

9. Глубокая копия

Когда нужно скопировать всю структуру объектов, существует deepcopy():

from copy import deepcopy


a = [[1, 2], [3, 4]]
b = deepcopy(a)


b[0].append(100)

Теперь внутренние списки тоже независимы.

Это уже:

a ─────► [ ───► [1, 2]
           └──► [3, 4] ]


b ─────► [ ───► [1, 2, 100]
           └──► [3, 4] ]
🧠 Главное правило сегодняшнего дня

Запомни не просто таблицу:

list mutable, int immutable.

А вот эту цепочку:

имя → объект → ссылка → изменяемость объекта

И тогда многие странности Python начинают становиться логичными.

5. *args — произвольное количество позиционных аргументов

Вот первая новая конструкция.

def total(*args):
    print(args)

Вызов:

total(1, 2, 3)

выведет:

(1, 2, 3)

Обрати внимание:

Это кортеж.

Почему кортеж?

Потому что количество аргументов заранее неизвестно.

Внутри функции можно делать обычный цикл.

def total(*args):
    result = 0


    for number in args:
        result += number


    return result

Теперь:

total(5, 10, 20)

вернёт:

35
6. **kwargs

Теперь ещё одна магия.

def show(**kwargs):
    print(kwargs)

Вызов:

show(name="Alex", age=20)

получит:

{
    "name": "Alex",
    "age": 20
}

То есть kwargs — это словарь.

Можно пройтись циклом:

for key, value in kwargs.items():
    print(key, value)

Получится примерно:

name Alex
age 20

def example(a, *args, **kwargs):

example(

    city="Moscow"
)

Получаем:

Переменная

	

Значение




a

	

10




args

	

(20, 30)

8. Распаковка *

Теперь обратная операция.

Есть список.

numbers = [10, 20, 30]

Функция:

def add(a, b, c):
    return a + b + c

Можно написать:

add(*numbers)

Это превращается в:

add(10, 20, 30)

Именно для этого используется *.

1. Что такое область видимости?

Область видимости (scope) — это место, где переменная доступна.

Самый простой пример:

x = 10


def test():
    y = 20
    print(y)


test()

Здесь:

x существует снаружи функции.

y существует только внутри test().

Попробуй представить это как комнаты.

Глобальная комната


x = 10


┌─────────────────┐
│  test()         │
│                 │
│  y = 20         │
└─────────────────┘

y не может выйти наружу.

2. Правило LEGB

Python ищет переменные всегда в одном порядке.

LEGB означает:

Буква

	

Где ищет




L

	

Local




E

	

Enclosing




G

B

	

Built-in

Получим:

test()

3. Почему возникает ошибка?

Посмотри внимательно.

    x = x + 1

Но нет.

Будет ошибка.

Потому что строка

делает x локальной переменной.

Получается примерно так:

Local


x = ?


x = x + 1

Python пытается использовать локальный x до того, как он получил значение.

4. global

Если действительно нужно изменить глобальную переменную:

Хороший код обычно возвращает значение через return, а не меняет глобальные переменные.

5. Теперь самое интересное — Enclosing

Это как раз тот вопрос, который был на диагностике.

Смотри.

def outer():
    x = 10

        print(x)


    inner()


outer()

Что происходит?

Комнаты выглядят так.

Global


┌──────────────┐
│ outer()      │
│              │
│ x = 10       │
│              │
│ ┌─────────┐  │

│ └─────────┘  │
└──────────────┘

Когда inner() ищет x:

Local → нет.

Enclosing → есть!

Поэтому печатает 10.

Именно это ты не знал на диагностике.

6. nonlocal

А что если inner() хочет изменить x?

Попробуем.

def outer():
    x = 10


    def inner():
        x += 1

Будет ошибка.

Почему?

По той же причине.

x становится локальной переменной inner().

Чтобы изменить переменную внешней функции:

def outer():
    x = 10


    def inner():
        nonlocal x
        x += 1


    inner()
    print(x)


outer()

Получим:

11

Запомни:

global — меняет глобальную переменную.

nonlocal — меняет переменную внешней функции.

7. Замыкание (Closure)

Теперь магия.

def make_multiplier(n):


    def multiply(x):
        return x * n


    return multiply

Использование.

double = make_multiplier(2)


print(double(5))

Получим:

10

Почему?

Когда функция вернулась, казалось бы, n должен исчезнуть.

Но нет.

Python сохранил его внутри возвращённой функции.

Это и называется замыканием.

Можно сделать ещё.

triple = make_multiplier(3)


print(triple(5))

Получим:

15

Теперь:

double помнит n = 2


triple помнит n = 3

Хотя обе функции были созданы одной и той же функцией.

Очень часто:

декораторы;

фабрики функций;

настройки обработчиков событий;

кэширование.

Когда будем проходить декораторы, ты увидишь, что они почти полностью построены на замыканиях.

1. Что такое исключение?

Посмотри:

number = int(input("Введите число: "))

Если пользователь введёт:

hello

Python не сможет превратить "hello" в int.

Возникнет:

ValueError

И программа остановится.

Это называется исключением (exception).

2. try / except

Мы можем сказать Python:

«Попробуй выполнить этот код. Если возникнет определённая ошибка — обработай её».

try:
    number = int(input("Введите число: "))
except ValueError:
    print("Нужно ввести число!")

Теперь вместо падения программы получим:

Нужно ввести число!
3. Почему лучше указывать конкретную ошибку?

Можно написать:

try:
    number = int(input())
except:
    print("Ошибка")

Но это плохая привычка.

Почему?

Потому что мы скрываем любую ошибку.

Например:

try:
    result = 10 / 0
except:
    print("Что-то пошло не так")

Мы потеряли информацию о том, что на самом деле произошло.

Лучше:

try:
    result = 10 / 0
except ZeroDivisionError:
    print("На ноль делить нельзя")
4. Несколько except

Можно обрабатывать разные ошибки отдельно:

try:
    number = int(input())
    result = 10 / number

except ValueError:
    print("Ты ввёл не число")

except ZeroDivisionError:
    print("На ноль делить нельзя")

Теперь поведение зависит от конкретной ошибки.

5. Exception

Вот здесь важный момент из твоей диагностики.

Exception — это базовый класс для большинства обычных исключений.

Например:

ValueError
ZeroDivisionError
TypeError
IndexError
KeyError

являются разновидностями исключений.

Поэтому можно написать:

try:
    ...
except Exception:
    print("Произошла ошибка")

Это поймает многие обычные ошибки.

Но:

Не стоит без причины использовать except Exception вместо конкретного типа.

Если ты ожидаешь ValueError, лучше написать ValueError.

6. Можно получить сам объект ошибки

Например:

try:
    number = int("hello")

except ValueError as error:
    print(error)

error содержит информацию об исключении.

Это удобно для логирования и диагностики.

7. else

Вот это часто забывают.

try:
    number = int(input())
except ValueError:
    print("Ошибка")
else:
    print("Всё получилось:", number)

else выполняется только если в try не произошло исключения.

То есть:

try
 ↓
ошибка?
 ↙     ↘
да      нет
 ↓       ↓
except  else
8. finally

А вот finally выполняется в любом случае.

try:
    number = int(input())
except ValueError:
    print("Ошибка")
finally:
    print("Программа завершила попытку")

Неважно:

произошла ошибка;
ошибки не было.

finally выполнится.

Это особенно полезно для освобождения ресурсов:

открыли файл
     ↓
работаем
     ↓
finally → закрываем

Именно поэтому ты встречал finally при работе с файлами и ресурсами.

9. raise

Теперь обратная сторона.

До этого мы ловили ошибки.

raise позволяет самому вызвать исключение.

Например:

age = -5

if age < 0:
    raise ValueError("Возраст не может быть отрицательным")

Python остановит выполнение и выдаст:

ValueError: Возраст не может быть отрицательным
10. Зачем это нужно?

Представь функцию:

def withdraw(balance, amount):
    ...

Мы можем запретить неправильное значение:

def withdraw(balance, amount):
    if amount < 0:
        raise ValueError("Сумма не может быть отрицательной")

    return balance - amount

Теперь функция сама гарантирует свои условия.

11. Очень важный принцип

Не надо делать так:

try:
    ...
except Exception:
    pass

Это называется примерно:

«Я не знаю, что произошло, поэтому просто сделаю вид, что ничего не произошло». 😄

Так можно случайно спрятать серьёзную ошибку.

Хорошая обработка исключений должна отвечать на вопрос:

🥋 День 5 — ООП: классы, объекты и self
1. Что такое класс?

Ты уже давал хорошую аналогию:

Класс — чертёж, объект — то, что построили по этому чертежу.

Именно так.

Например:

class Dog:
    pass

Dog — это класс.

Создаём объект:

dog = Dog()

Теперь:

Dog
 ↓
класс / чертёж

dog
 ↓
конкретный объект

Можно создать сколько угодно объектов одного класса:

dog1 = Dog()
dog2 = Dog()
dog3 = Dog()

Все они созданы по одному чертежу, но являются разными объектами.

2. Атрибуты объекта

Допустим:

class Dog:
    def __init__(self, name):
        self.name = name

Теперь:

dog = Dog("Rex")

Внутри объекта появится:

dog
 └── name → "Rex"

Можно обратиться:

print(dog.name)

Получим:

Rex
3. Что такое __init__?

__init__ — специальный метод, который вызывается при создании объекта.

Когда ты пишешь:

dog = Dog("Rex")

Python вызывает:

__init__(...)

и передаёт туда "Rex".

Поэтому:

class Dog:
    def __init__(self, name):
        self.name = name

можно примерно воспринимать как:

«Когда создаёшь Dog — положи переданное имя внутрь этого объекта».

4. А что такое self?

Вот здесь очень важно.

class Dog:
    def __init__(self, name):
        self.name = name

self — это ссылка на конкретный объект, с которым сейчас работает метод.

Например:

dog1 = Dog("Rex")
dog2 = Dog("Bob")

У них будут разные self.

Условно:

dog1 → self → dog1
             name = "Rex"

dog2 → self → dog2
             name = "Bob"

Поэтому:

print(dog1.name)

→ Rex

а:

print(dog2.name)

→ Bob

5. Методы

Метод — это функция, принадлежащая классу.

class Dog:
    def __init__(self, name):
        self.name = name

    def bark(self):
        print(f"{self.name}: Woof!")

Теперь:

dog = Dog("Rex")
dog.bark()

Получим:

Rex: Woof!

Обрати внимание:

self.name

позволяет методу обратиться к данным конкретного объекта.

6. Что на самом деле происходит с dog.bark()?

Вот это интересный момент.

Когда ты пишешь:

dog.bark()

Python фактически передаёт объект dog в метод как self.

Упрощённо можно представить:

Dog.bark(dog)

Именно поэтому метод объявляется:

def bark(self):

а вызывается:

dog.bark()

Ты сам self при обычном вызове не передаёшь — Python делает это автоматически.

7. Атрибут класса и атрибут объекта

Смотри:

class Dog:
    species = "Canis familiaris"

    def __init__(self, name):
        self.name = name

Здесь:

species

— атрибут класса.

А:

self.name

— атрибут конкретного объекта.

Поэтому:

dog1 = Dog("Rex")
dog2 = Dog("Bob")

У обоих:

dog1.species
dog2.species

будет одно и то же значение.

Но:

dog1.name
dog2.name

разные.

8. Изменение атрибута

Если:

dog = Dog("Rex")

можно сделать:

dog.name = "Max"

Теперь:

print(dog.name)

→ Max.

Объекты по умолчанию не являются неизменяемыми.

9. Наследование

Теперь следующий уровень.

Допустим, есть:

class Animal:
    def eat(self):
        print("Eating")

Создадим:

class Dog(Animal):
    def bark(self):

🥋 День 6 — Инкапсуляция
1. Зачем вообще нужна инкапсуляция?

Представь банковский счёт:

class BankAccount:
    def __init__(self, balance):
        self.balance = balance

Мы можем сделать:

account = BankAccount(1000)
account.balance = -500000

Технически Python это позволит.

Но с точки зрения логики программы — странно. 😄

Мы хотим, чтобы баланс изменялся контролируемым способом:

account.deposit(500)
account.withdraw(200)

То есть объект сам отвечает за корректность своего состояния.

2. Публичные атрибуты

Обычный атрибут:

self.name = name

считается публичным.

Его можно использовать напрямую:

user.name

и менять:

user.name = "Bob"
3. _name — защищённый атрибут

В Python можно написать:

self._balance = balance

Один _ означает примерно:

«Это внутренний атрибут. Пожалуйста, не трогай его напрямую без необходимости».

Но важный момент:

Python технически не запрещает доступ.

Можно:

account._balance

Это скорее соглашение между разработчиками, чем настоящая защита.

4. __balance — приватный атрибут

А вот два подчёркивания:

self.__balance = balance

работают интереснее.

Например:

class BankAccount:
    def __init__(self, balance):
        self.__balance = balance

Теперь:

account = BankAccount(1000)

print(account.__balance)

даст ошибку.

Python изменяет имя атрибута внутри объекта. Это называется name mangling.

Условно:

__balance
    ↓
_BankAccount__balance

Поэтому напрямую обратиться к account.__balance нельзя обычным способом.

5. Но зачем это нужно?

Например:

class BankAccount:
    def __init__(self, balance):
        self.__balance = balance

    def deposit(self, amount):
        if amount > 0:
            self.__balance += amount

    def get_balance(self):
        return self.__balance

Теперь пользователь класса не должен напрямую менять баланс:

account = BankAccount(1000)

account.deposit(500)

print(account.get_balance())

Получаем:

1500

А если:

account.deposit(-100000)

метод может просто не позволить это сделать.

6. Но есть проблема с get_balance()

В Python часто вместо:

account.get_balance()

хочется писать:

account.balance

И здесь появляется очень важный механизм:

@property
7. @property

Смотри:

class BankAccount:
    def __init__(self, balance):
        self.__balance = balance

    @property
    def balance(self):
        return self.__balance

Теперь:

account = BankAccount(1000)

print(account.balance)

вызывает метод balance, но выглядит как обычный атрибут.

То есть:

account.balance

фактически вызывает:

balance()

но круглые скобки писать не нужно.

8. @property + @setter

А теперь самое интересное.

Мы можем контролировать и получение, и изменение значения:

class Person:
    def __init__(self, age):
        self.__age = age

    @property
    def age(self):
        return self.__age

    @age.setter
    def age(self, value):
        if value < 0:
            raise ValueError("Age cannot be negative")

        self.__age = value

Теперь:

person = Person(25)

print(person.age)

→ 25

А:

person.age = 30

разрешено.

Но:

person.age = -10

вызовет:

ValueError

То есть мы получили контролируемый доступ:

person.age
    ↓
 getter → получить значение


person.age = 30
    ↓
 setter → проверить и изменить значение
🧠 Главное различие

Запомни пока так:

Запись	Смысл
self.name	публичный атрибут
self._name	внутренний атрибут, соглашение
self.__name	name mangling / «приватный» атрибут
@property	контролируемое получение значения
@name.setter	контролируемое изменение значения

И важная оговорка:

В Python нет такой жёсткой приватности, как, например, в некоторых других языках. Даже __name технически можно найти через преобразованное имя.

🥋 День 7 — @classmethod и @staticmethod

После сегодняшнего занятия ты должен чётко понимать разницу между:

self
cls

и обычным методом без них.

1. Обычный метод — self

Начнём с того, что уже знаем:

class User:
    def __init__(self, name):
        self.name = name

    def say_hello(self):
        return f"Hello, {self.name}!"

Создаём объект:

user = User("Alex")

Когда пишем:

user.say_hello()

Python фактически передаёт объект в метод:

User.say_hello(user)

Поэтому:

def say_hello(self):

self — это конкретный объект.

2. @classmethod

Теперь появляется cls.

class User:
    count = 0

    def __init__(self, name):
        self.name = name
        User.count += 1

    @classmethod
    def get_count(cls):
        return cls.count

Используем:

user1 = User("Alex")
user2 = User("Bob")

print(User.get_count())

Получим:

2
Что такое cls?

Очень просто:

self → конкретный объект
cls  → сам класс

То есть:

user1

— это объект.

А:

User

— это класс.

@classmethod получает именно класс.

3. Зачем нужен @classmethod?

Одна из самых распространённых причин — альтернативный способ создания объекта.

Например:

class User:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    @classmethod
    def from_string(cls, data):
        name, age = data.split(",")
        return cls(name, int(age))

Теперь можем написать:

user = User.from_string("Alex,25")

Вместо:

user = User("Alex", 25)

Внутри:

return cls(name, int(age))

cls здесь — это User.

То есть фактически:

return User(name, int(age))

Но cls лучше, потому что сохраняет работоспособность при наследовании.

4. @staticmethod

Теперь третий вариант.

class Math:

    @staticmethod
    def add(a, b):
        return a + b

Можно написать:

print(Math.add(5, 3))

Получим:

8

И здесь нет:

self

и нет:

cls

Почему?

Потому что этому методу вообще не нужен ни объект, ни класс.

Он просто логически относится к классу.

Например:

class Math:

    @staticmethod
    def is_even(number):
        return number % 2 == 0

Используем:

print(Math.is_even(10))

Получим:

True
🧠 Главная таблица дня

Запомни её:

Метод	Первый параметр	Имеет доступ к
обычный	self	объекту
@classmethod	cls	классу
@staticmethod	ничего	ни к объекту, ни к классу

То есть:

обычный метод
     ↓
   self
     ↓
конкретный объект
classmethod
     ↓
    cls
     ↓
    класс
staticmethod
     ↓
 ничего
     ↓
обычная функция внутри класса
⚠️ Важный нюанс

staticmethod не означает «более быстрый метод» или «особый метод».

Это просто способ сказать:

«Эта функция логически относится к этому классу, но ей не нужен ни объект, ни сам класс».

🐍 День 8 — специальные методы
1. Что такое __str__?

Представим обычный класс:

class User:
    def __init__(self, name, age):
        self.name = name
        self.age = age


user = User("Alex", 25)

print(user)

Без специального метода Python не знает, как красиво представить объект.

Поэтому мы можем определить:

class User:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def __str__(self):
        return f"User: {self.name}, age: {self.age}"

Теперь:

print(user)

даст:

User: Alex, age: 25
Что здесь происходит?

Когда ты пишешь:

print(user)

Python примерно обращается к:

str(user)

а str(user) использует:

user.__str__()

То есть:

print(user)
    ↓
str(user)
    ↓
user.__str__()
2. __repr__

Есть ещё:

__repr__

Он предназначен для технического представления объекта, особенно полезного разработчику.

Например:

class User:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def __repr__(self):
        return f"User(name={self.name!r}, age={self.age})"

Теперь:

user = User("Alex", 25)

print(user)

Если __str__ нет, Python может использовать __repr__ как запасной вариант.

Получим:

User(name='Alex', age=25)

Для начала запомни:

__str__  → человеку
__repr__ → разработчику
3. __len__

А теперь интереснее.

Допустим, у нас есть корзина:

class Cart:
    def __init__(self):
        self.items = []

Мы хотим:

cart = Cart()

cart.items.append("Apple")
cart.items.append("Milk")

print(len(cart))

Но без __len__ Python не знает, как определить длину Cart.

Добавляем:

class Cart:
    def __init__(self):
        self.items = []

    def __len__(self):
        return len(self.items)

Теперь:

len(cart)

фактически вызывает:

cart.__len__()
4. __eq__ — сравнение объектов

Вот здесь очень важный момент.

class User:
    def __init__(self, name):
        self.name = name

Создадим:

user1 = User("Alex")
user2 = User("Alex")

Что будет?

print(user1 == user2)

По умолчанию это будет:

False

Потому что это два разных объекта.

Если мы хотим определить собственное правило сравнения:

class User:
    def __init__(self, name):
        self.name = name

    def __eq__(self, other):
        return self.name == other.name

Теперь:

user1 = User("Alex")
user2 = User("Alex")

print(user1 == user2)

Получим:

True

Потому что:

user1 == user2

примерно означает:

user1.__eq__(user2)
5. __lt__ — меньше

Можно определить поведение <.

Например:

class User:
    def __init__(self, age):
        self.age = age

    def __lt__(self, other):
        return self.age < other.age

Теперь:

alex = User(25)
bob = User(30)

print(alex < bob)

Получим:

True

Потому что Python вызывает примерно:

alex.__lt__(bob)
6. __add__ — оператор +

Это уже настоящая магия. 😎

Создадим:

class Money:
    def __init__(self, amount):
        self.amount = amount

    def __add__(self, other):
        return Money(self.amount + other.amount)

Теперь:

money1 = Money(100)
money2 = Money(50)

money3 = money1 + money2

Python примерно делает:

money3 = money1.__add__(money2)

И:

money3.amount

будет:

150
7. __getitem__

Можно сделать объект похожим на список или словарь.

class Cart:
    def __init__(self):
        self.items = ["Apple", "Milk", "Bread"]

    def __getitem__(self, index):
        return self.items[index]

Теперь:

cart = Cart()

print(cart[0])

Python вызывает:

cart.__getitem__(0)

Результат:

Apple

И даже:

print(cart[1])

работает.

🧠 Главная идея сегодняшнего дня

Вот эта таблица — твоя шпаргалка:

Синтаксис	Специальный метод
str(obj) / print(obj)	__str__
repr(obj)	__repr__
len(obj)	__len__
a == b	__eq__
a < b	__lt__
a + b	__add__
obj[index]	__getitem__

То есть специальные методы позволяют сказать Python:

«Когда пользователь пишет такой обычный Python-синтаксис, вот как должен вести себя мой объект».

1. Теория
Наследование мы уже проходили в День 5, поэтому повторять всё с нуля не будем. Сегодня углубим понимание.
1.1. Переопределение методов
class Animal:    def speak(self):        return "Some sound"class Dog(Animal):    def speak(self):        return "Woof!"



animal = Animal()dog = Dog()print(animal.speak())  # Some soundprint(dog.speak())     # Woof!



В Dog есть собственный speak(), поэтому Python использует его вместо унаследованного метода Animal.speak().
При этом другие методы родителя по-прежнему доступны, если дочерний класс их не переопределяет.
1.2. Как правильно понимать super()
class Animal:    def __init__(self, name):        self.name = name    def describe(self):        return f"My name is {self.name}"class Dog(Animal):    def __init__(self, name, breed):        super().__init__(name)        self.breed = breed    def describe(self):        parent_description = super().describe()        return f"{parent_description}, breed: {self.breed}"



dog = Dog("Rex", "Husky")print(dog.describe())



Результат:
My name is Rex, breed: Husky


Здесь важно различать две вещи:
- super().__init__(name) запускает родительскую инициализацию имени.
- super().describe() вызывает реализацию describe() из родительского класса.
super() не создаёт родительский объект и не заменяет self. Он помогает обратиться к следующей подходящей реализации метода в порядке поиска методов класса.
1.3. Полиморфизм
Представь, что программа умеет отправлять разные уведомления.
class EmailNotification:    def send(self):        return "Sending email"class SMSNotification:    def send(self):        return "Sending SMS"



Оба класса имеют метод send(), но выполняют разные действия.
notifications = [    EmailNotification(),    SMSNotification(),]for notification in notifications:    print(notification.send())



Результат:
Sending email
Sending SMS


Циклу не нужно проверять тип каждого объекта. Он просто вызывает send().
Это и есть полиморфизм: единый интерфейс, за которым может стоять разное поведение.
В Python для такого полиморфизма не всегда требуется наследование. Достаточно, чтобы объекты поддерживали нужный метод.
1.4. Наследование или композиция?
- Наследование: Dog является Animal.
- Композиция: Car имеет Engine.
Если класс должен быть разновидностью другого класса, наследование может быть подходящим решением. Если объект просто содержит другой объект и использует его возможности, часто лучше композиция.
Не нужно наследоваться от класса только ради того, чтобы получить доступ к его методу.

2. Разбор примеров
Посмотри на следующий код:
class Animal:    def __init__(self, name):        self.name = name    def speak(self):        return "Sound"class Cat(Animal):    def speak(self):        return super().speak() + " — Meow"



Когда выполняется Cat("Murka"), у объекта появляется name благодаря родительскому __init__.
А когда выполняется cat.speak(), дочерний метод вызывает родительский и добавляет к результату свою строку.
Получается:
cat = Cat("Murka")print(cat.speak())



Sound — Meow
