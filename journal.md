1. Самая важная мысль

Начнём с того, что немного изменим твоё привычное представление.

Ты раньше говорил примерно так:

«Переменная a хранит значение 10».

Для начала это удобная модель. Но технически правильнее думать так:

Имя a ссылается на объект 10.

Например:

a = 10

Можно представить это так:

a ───────► 10

a — это имя.

10 — это объект.

И это очень важно.

2. А что происходит здесь?
a = 10
b = a

Не создаётся ситуация:

a ──► 10
b ──► 10

в смысле «у каждого своя копия».

Мы можем представить это так:

       ┌──────► 10
a ─────┤
b ─────┘

Оба имени ссылаются на один объект.

Проверить идентичность объектов можно с помощью is:

a = 10
b = a


print(a == b)
print(a is b)
3. == против is

Вот здесь запомни фундаментальное различие.

==

Проверяет:

равны ли значения объектов?

a = [1, 2, 3]
b = [1, 2, 3]


print(a == b)

Получим:

True

Потому что содержимое одинаковое.

Но:

print(a is b)

даст:

False

Потому что это два разных объекта.

Можно представить:

a ───► [1, 2, 3]


b ───► [1, 2, 3]

Содержимое одинаковое → == → True.

Объекты разные → is → False.

Коротко:
==  → равенство
is  → идентичность
4. Теперь самое интересное — изменяемость

Объекты в Python условно делятся на:

Immutable — неизменяемые

Например:

int
float
bool
str
tuple
Mutable — изменяемые

Например:

list
dict
set

И вот здесь нужно немного поправить твоё представление из диагностики.

Когда ты делаешь:

x = 10
x = 20

не происходит изменения объекта 10.

Происходит примерно это:

x ───► 10


x ───► 20

Имя x просто перестало ссылаться на старый объект и стало ссылаться на другой.

5. Почему со списком всё иначе?

Смотри:

numbers = [1, 2, 3]


numbers.append(4)

Здесь объект списка изменяется:

numbers ───► [1, 2, 3]
                    ↓
numbers ───► [1, 2, 3, 4]

Сам объект остался тем же.

6. И теперь тот самый момент из диагностики
a = [1, 2, 3]
b = a


b.append(4)


print(a)
print(b)

Что здесь произошло?

После:

b = a

получаем:

a ─────┐
       ▼
   [1, 2, 3]
       ▲
       │
b ─────┘

А потом:

b.append(4)

мы изменяем сам объект списка.

Поэтому:

a → [1, 2, 3, 4]
b → [1, 2, 3, 4]

Это не потому, что b каким-то образом «изменил a.

Они вообще указывали на один и тот же список.

7. Как сделать отдельную копию?

Можно:

a = [1, 2, 3]
b = a.copy()


b.append(4)

Теперь:

a ───► [1, 2, 3]


b ───► [1, 2, 3, 4]

И:

print(a)

даст:

[1, 2, 3]
8. Но тут есть ловушка 👀

Посмотри:

a = [[1, 2], [3, 4]]
b = a.copy()

На первый взгляд кажется, что мы полностью скопировали a.

Но это поверхностная копия.

Условно:

a ─────► [ ───► [1, 2]
           └──► [3, 4] ]


b ─────► [ ───► [1, 2]
           └──► [3, 4] ]

Внешние списки разные.

Но внутренние списки всё ещё общие.

Поэтому:

b[0].append(100)

может изменить и a.

9. Глубокая копия

Когда нужно скопировать всю структуру объектов, существует deepcopy():

from copy import deepcopy


a = [[1, 2], [3, 4]]
b = deepcopy(a)


b[0].append(100)

Теперь внутренние списки тоже независимы.

Это уже:

a ─────► [ ───► [1, 2]
           └──► [3, 4] ]


b ─────► [ ───► [1, 2, 100]
           └──► [3, 4] ]
🧠 Главное правило сегодняшнего дня

Запомни не просто таблицу:

list mutable, int immutable.

А вот эту цепочку:

имя → объект → ссылка → изменяемость объекта

И тогда многие странности Python начинают становиться логичными.

Значение

5. *args — произвольное количество позиционных аргументов

Вот первая новая конструкция.

def total(*args):
    print(args)

Вызов:

total(1, 2, 3)

выведет:

(1, 2, 3)

Обрати внимание:

Это кортеж.

Почему кортеж?

Потому что количество аргументов заранее неизвестно.

Внутри функции можно делать обычный цикл.

def total(*args):
    result = 0


    for number in args:
        result += number


    return result

Теперь:

total(5, 10, 20)

вернёт:

35
6. **kwargs

Теперь ещё одна магия.

def show(**kwargs):
    print(kwargs)

Вызов:

show(name="Alex", age=20)

получит:

{
    "name": "Alex",
    "age": 20
}

То есть kwargs — это словарь.

Можно пройтись циклом:

for key, value in kwargs.items():
    print(key, value)

Получится примерно:

name Alex
age 20

def example(a, *args, **kwargs):

Например:

example(

    city="Moscow"
)

Получаем:

Переменная

	

Значение




a

	

10




args

	

(20, 30)




kwargs

	

{"name":"Alex","city":"Moscow"}

8. Распаковка *

Теперь обратная операция.

Есть список.

numbers = [10, 20, 30]

Функция:

def add(a, b, c):
    return a + b + c

Можно написать:

add(*numbers)

Это превращается в:

add(10, 20, 30)

Именно для этого используется *.

greet(**user)

Python автоматически сделает:

обычные параметры

*args

Передать список как аргументы

1. Что такое область видимости?

Область видимости (scope) — это место, где переменная доступна.

Самый простой пример:

x = 10


def test():
    y = 20
    print(y)


test()
print(x)

Здесь:

x существует снаружи функции.

y существует только внутри test().

Попробуй представить это как комнаты.

Глобальная комната


x = 10


┌─────────────────┐
│  test()         │
│                 │
│  y = 20         │
└─────────────────┘

y не может выйти наружу.

2. Правило LEGB

Python ищет переменные всегда в одном порядке.

LEGB означает:

Буква

	

Где ищет




L

	

Local




E

	

Enclosing




G

	

Global




B

	

Built-in

Именно в таком порядке.

L — Local
x = 100


def test():
    x = 10
    print(x)


test()

Что найдёт Python?

Сначала смотрит локально.

Получим:

10

Внешний x даже не понадобится.

G — Global
x = 100


def test():
    print(x)


test()

Внутри функции собственного x нет.

Python идёт дальше.

Находит глобальный.

Получим:

100
3. Почему возникает ошибка?

Посмотри внимательно.

x = 10


def test():
    x = x + 1

На первый взгляд кажется, что получится 11.

Но нет.

Будет ошибка.

Почему?

Потому что строка

x = ...

делает x локальной переменной.

Получается примерно так:

Local


x = ?


x = x + 1

Python пытается использовать локальный x до того, как он получил значение.

4. global

Если действительно нужно изменить глобальную переменную:

x = 10


def test():
    global x
    x += 1


test()
print(x)

Получим:

11

Но важное правило.

global используют редко.

Хороший код обычно возвращает значение через return, а не меняет глобальные переменные.

5. Теперь самое интересное — Enclosing

Это как раз тот вопрос, который был на диагностике.

Смотри.

def outer():
    x = 10


    def inner():
        print(x)


    inner()


outer()

Что происходит?

Комнаты выглядят так.

Global


┌──────────────┐
│ outer()      │
│              │
│ x = 10       │
│              │
│ ┌─────────┐  │
│ │ inner() │  │
│ └─────────┘  │
└──────────────┘

Когда inner() ищет x:

Local → нет.

Enclosing → есть!

Поэтому печатает 10.

Именно это ты не знал на диагностике.

6. nonlocal

А что если inner() хочет изменить x?

Попробуем.

def outer():
    x = 10


    def inner():
        x += 1

Будет ошибка.

Почему?

По той же причине.

x становится локальной переменной inner().

Чтобы изменить переменную внешней функции:

def outer():
    x = 10


    def inner():
        nonlocal x
        x += 1


    inner()
    print(x)


outer()

Получим:

11

Запомни:

global — меняет глобальную переменную.

nonlocal — меняет переменную внешней функции.

7. Замыкание (Closure)

Теперь магия.

def make_multiplier(n):


    def multiply(x):
        return x * n


    return multiply

Использование.

double = make_multiplier(2)


print(double(5))

Получим:

10

Почему?

Когда функция вернулась, казалось бы, n должен исчезнуть.

Но нет.

Python сохранил его внутри возвращённой функции.

Это и называется замыканием.

Можно сделать ещё.

triple = make_multiplier(3)


print(triple(5))

Получим:

15

Теперь:

double помнит n = 2


triple помнит n = 3

Хотя обе функции были созданы одной и той же функцией.

Где это используют?

Очень часто:

декораторы;

фабрики функций;

настройки обработчиков событий;

кэширование.

Когда будем проходить декораторы, ты увидишь, что они почти полностью построены на замыканиях.

Главное запомнить

Сегодня разберём:

что такое исключения;
try / except;
конкретные типы исключений;
Exception;
else;

raise;
как создавать собственные ошибки;

1. Что такое исключение?

Посмотри:

number = int(input("Введите число: "))

Если пользователь введёт:

hello

Python не сможет превратить "hello" в int.

Возникнет:

ValueError

И программа остановится.

Это называется исключением (exception).

2. try / except

Мы можем сказать Python:

«Попробуй выполнить этот код. Если возникнет определённая ошибка — обработай её».

try:
    number = int(input("Введите число: "))
except ValueError:
    print("Нужно ввести число!")

Теперь вместо падения программы получим:

Нужно ввести число!
3. Почему лучше указывать конкретную ошибку?

Можно написать:

try:
    number = int(input())
except:
    print("Ошибка")

Но это плохая привычка.

Почему?

Потому что мы скрываем любую ошибку.

Например:

try:
    result = 10 / 0
except:
    print("Что-то пошло не так")

Мы потеряли информацию о том, что на самом деле произошло.

Лучше:

try:
    result = 10 / 0
except ZeroDivisionError:
    print("На ноль делить нельзя")
4. Несколько except

Можно обрабатывать разные ошибки отдельно:

try:
    number = int(input())
    result = 10 / number

except ValueError:
    print("Ты ввёл не число")

except ZeroDivisionError:
    print("На ноль делить нельзя")

Теперь поведение зависит от конкретной ошибки.

5. Exception

Вот здесь важный момент из твоей диагностики.

Exception — это базовый класс для большинства обычных исключений.

Например:

ValueError
ZeroDivisionError
TypeError
IndexError
KeyError

являются разновидностями исключений.

Поэтому можно написать:

try:
    ...
except Exception:
    print("Произошла ошибка")

Это поймает многие обычные ошибки.

Но:

Не стоит без причины использовать except Exception вместо конкретного типа.

Если ты ожидаешь ValueError, лучше написать ValueError.

6. Можно получить сам объект ошибки

Например:

try:
    number = int("hello")

except ValueError as error:
    print(error)

error содержит информацию об исключении.

Это удобно для логирования и диагностики.

7. else

Вот это часто забывают.

try:
    number = int(input())
except ValueError:
    print("Ошибка")
else:
    print("Всё получилось:", number)

else выполняется только если в try не произошло исключения.

То есть:

try
 ↓
ошибка?
 ↙     ↘
да      нет
 ↓       ↓
except  else
8. finally

А вот finally выполняется в любом случае.

try:
    number = int(input())
except ValueError:
    print("Ошибка")
finally:
    print("Программа завершила попытку")

Неважно:

произошла ошибка;
ошибки не было.

finally выполнится.

Это особенно полезно для освобождения ресурсов:

открыли файл
     ↓
работаем
     ↓
finally → закрываем

Именно поэтому ты встречал finally при работе с файлами и ресурсами.

9. raise

Теперь обратная сторона.

До этого мы ловили ошибки.

raise позволяет самому вызвать исключение.

Например:

age = -5

if age < 0:
    raise ValueError("Возраст не может быть отрицательным")

Python остановит выполнение и выдаст:

ValueError: Возраст не может быть отрицательным
10. Зачем это нужно?

Представь функцию:

def withdraw(balance, amount):
    ...

Мы можем запретить неправильное значение:

def withdraw(balance, amount):
    if amount < 0:
        raise ValueError("Сумма не может быть отрицательной")

    return balance - amount

Теперь функция сама гарантирует свои условия.

11. Очень важный принцип

Не надо делать так:

try:
    ...
except Exception:
    pass

Это называется примерно:

«Я не знаю, что произошло, поэтому просто сделаю вид, что ничего не произошло». 😄

Так можно случайно спрятать серьёзную ошибку.

Хорошая обработка исключений должна отвечать на вопрос:

Какую конкретно проблему я ожидаю и что я буду делать, если она произойдёт?
